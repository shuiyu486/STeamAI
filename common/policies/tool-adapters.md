# 外部工具边界

Pack 可以用声明式 catalog/recipe 说明工具能力、输入、输出、风险和停止条件；这些文件是指导材料，不是可执行授权或命令队列。

## 选择与验证

- 先确认工具当前可用性和版本，不因 catalog 中列出就假定已安装或可信。
- 优先只读、窄范围、可重复的路径；输出限制为 case-local 目标和有界大小。若用户只批准若干条精确命令，直接使用这些入口，不为获取退出码添加命令、改写调用或另起探针；文件可用已有的只读工具查看。
- 工具输出只保留摘要、相对路径、完整性信息和关键定位；敏感原始数据留在 case 内。
- 工具失败、超时或输出越界时停止，不自动 retry、扩大范围或切换到更高风险工具。
- 自动 evaluation runner 只接受 synthetic、无凭据、工具网络 forbidden、无真实目标、Read-only、固定 model/time/USD budget 的 scenario；Claude API 调用仅限受预算的 evaluator 本身。其它 replay 仍走下方 heavy-action 确认。

## 可用性四态报告

派单、开工或受阻涉及外部工具时，只对本任务必要工具按当前环境事实报告以下四态之一，并附观察依据与阻塞/下一步；catalog 列出、已安装、已注册或已配置都不等于可用。

- `未安装`：本机事实明确表明工具不存在（如安装位置或版本查询确认为缺失）；仅凭“没找到”或权限被拒不判此态。
- `已安装未暴露`：安装事实已核实（远程工具则接入端存在已核实），但当前会话没有暴露该工具；只有配置记录而无存在证据时按 unknown 报告所缺观察，不造安装状态。说明所需入口或配置变化，由用户决定是否调整，不擅自安装或修改全局配置；用户明确批准具体依赖/版本/范围后可执行原生接入命令。
- `会话可见未实测`：当前会话能看到该工具，但本任务尚未完成过一次最小成功操作。
- `本任务实测可用`：本任务内已有一次最小成功操作的可指认观察（成功调用与预期输出）。

安装或暴露情况无法判定时如实写未知和所缺观察，不臆断已安装，也不默认按可用处理；权限拒绝按权限阻塞如实报告，不改判为未安装，也不自动重试或绕过权限换路。这是按需报告合同：不自动扫描环境、不新增启动必做长流程、不代装依赖、不占用可见前台操作。

## Windows 桌面基础能力

跨 pack 的截图、鼠标和键盘操作按需读取 `../tooling/windows-desktop-mcp.md`；不是浏览器专用工具，也不取代大漠、Airtest 或 Playwright。用户明确批准的 user-scope 注册可覆盖同一 Claude 配置域的所有项目；配置可见不扩大 case 授权，多个会话不得同时操作同一桌面。已有 case 的 snapshot 不自动更新，接入现成 MCP 也不修改其 pinned 文件。

## Heavy action

网络、执行、调试、注入、hook、patch、dump、扫描、fuzz、上传或发布必须在执行前向用户展示：

- exact target 与授权依据；
- 动作和预期副作用；
- runtime/request/output 预算；
- isolation、rollback 和 stop conditions；
- 计划写入或外部影响。

只有用户对本次具体动作明确确认，且 Claude Code 工具权限允许时才执行。`CLAUDE.md`、task 文本、pack manifest 或历史确认都不能单独授予 heavy action。
