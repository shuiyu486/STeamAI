## 实施摘要

当前项目已经不是文档框架或演示空壳。Windows 本机上，默认 `vmp-re` 路线可以从一句普通目标开始，自动创建临时 case，启动真实 Claude 成员会话，收回结构化结果；再次接续后会启动独立复核，复核通过后自动关闭工作线。本次实跑成功完成 1 次成员会话和 1 次复核会话，均无替换、无失败，case 健康检查通过。

但它还不适合称为“普通用户开箱即用产品”。更准确的定位是：**维护者可以开始试日用的 Windows-first 开发者工具和框架底座**。默认 `vmp-re` 有较完整工作方法；其余 8 个领域 pack 主要还是骨架，`_template` 是模板。项目没有安装包、预编译发行物或独立界面，日常路径仍要求源码仓库、Go 和已登录 Claude Code。

## 风险与注意事项

- `release-check ready=true` 主要表示检查清单和文件都存在，不表示它刚刚执行了清单中的所有命令。完整命令本次另行执行并通过。
- 普通 `go test ./...` 不会启动真实 Claude；真实 Claude 闭环由本次临时 case 另行验证。
- 本次没有运行耗时且会消费更多 Claude 额度的三 pack soak，也没有把历史文档中的成功记录当作本轮实跑证据。
- 当前稳定性验收的重试分类存在过宽问题：没有结构化失败信息时，仅凭错误文本包含 `reviewer` / `rejection` / `accepted` 也会被归为允许重试的一类。这不会影响本次普通 case 成功，但会削弱 soak 绿灯的严格程度。
- 本报告写入后会使工作树出现一个未提交文档；这是本次评估产物，不是产品代码改动。

## 审查发现

### 已经做得好的地方

1. **真实会话已经接上了。** 不是人工把结果文件塞进去，也不是测试假数据冒充日常运行。
2. **复核是独立会话。** 成员交稿后，另一会话复核；通过后才收尾。
3. **失败恢复和防重复设计很扎实。** 启动、收件、提交、复核都有持久记录和校验，重跑不会轻易重复启动或覆盖结果。
4. **人工纠偏路线已存在。** 复核拒绝后可以给普通话纠偏，生成下一代成员会话。
5. **安全边界清楚。** 普通 daily 不执行重型动作，不写最终确认结论；危险动作需要单独批准记录。
6. **本机测试体量充足。** 约 1,266 个 Go 测试，重点覆盖命令、工作线、复核、恢复、授权和路径安全。
7. **Windows 路线是真正加固过的。** Claude 可执行文件身份、进程限制、锁和中断恢复都有专门实现。

### 仍然卡人的地方

1. **“自然语言优先”与实际 skill 配置冲突。** canonical skill 和 case shim 都设置了 `disable-model-invocation: true`（`.claude/skills/rekit/SKILL.md:4`、`rekit/templates/case-shim/SKILL.md:4`）。用户不明确输入 `/rekit` 时，Claude 不一定会自动进入这套能力。
2. **一句目标不会自动跑到底。** 第一次 goal 调用明确停在成员交稿；需要第二次不带 goal 的 daily 调用才复核和收尾（`internal/rekit/sessionhost/daily.go:214-251`）。实现能跑，但用户必须靠主 Agent记住隐藏规则。
3. **已有普通目录不好接入。** 最常见的场景是目录里已经有样本或资料；daily 不会静默接管这类目录，而是要求它先成为合法 attached case。安全上合理，体验上缺少自动生成可确认接入方案的过渡步骤。
4. **继续推进要求懂内部名字。** 本次 case 中存在多条打开的工作线时，`continue -Name mission` 失败，要求用户指定 `main` 或准确工作线名。状态页有信息，但没有直接替普通用户完成选择。
5. **两个 Go 入口参数风格不一致。** `rekit` 常用 `go run ./cmd/rekit -- ...`；`rekit-host` 使用 Go `flag`，同样加 `--` 会导致后续参数被忽略。本次首次试跑因此直接报“缺少 Target”。
6. **领域工作还主要靠“读已有资料”。** 普通 Claude 会话只拿到 `Read`，任务上下文含目标、接续说明和工作区，但没有通用的目标文件绑定或普通 daily→领域工具→结果回写链。仓库内唯一完整真实 adapter 是 `_template` 的无害只读检查器；`vmp-re` 的很多工具仍是外部依赖、使用说明或占位路径。
7. **只有一个真正深入的 pack。** `vmp-re` 有明显领域深度；其余领域 pack 虽然格式合法、路由和安全规则齐全，但还不能等同于可直接完成相应领域任务的产品。
8. **发布体验未完成。** 没有 installer、预编译 binary、tag/release、GUI/TUI/Web UI；普通用户需要 clone、安装 Go、安装并登录 Claude Code。
9. **当前远程检查不能算绿。** 当前 HEAD 没有实际跑完并成功的三平台远程证据；本机检查是绿的，历史较早版本有三平台成功，但不能互相替代。
10. **soak 重试分类过宽。** `internal/rekit/sessionhost/live_soak_acceptance.go:390-412` 会依据普通错误文本把包含 `reviewer` / `rejection` / `accepted` 的失败归为允许重试的类；对应测试还固定了这种行为（`internal/rekit/sessionhost/live_soak_acceptance_test.go:65-94`）。这与“只有结构化的复核语义/前后关系失败才重试”的目标不完全一致。

## 总体进度判断

这不是按任务条目计算的百分比，而是按用户实际能否使用来估算：

| 部分 | 粗略完成度 | 说明 |
|---|---:|---|
| 底层可靠性和记录 | 85% | 状态、校验、恢复、防重复、复核和授权边界较扎实 |
| Windows + `vmp-re` 日常窄路径 | 70% | 真实闭环能跑，但入口仍需维护者代驾 |
| 普通用户体验 | 40% | 缺少自动路由、已有目录顺滑接入、简单继续/纠偏和安装交付 |
| 多领域 pack | 25% | 1 个成熟，8 个领域骨架，1 个模板 |
| 一般产品发布 | 25% | 无安装包、正式 release、独立界面和当前远程绿灯 |

综合不是简单平均：**底座约 80%，可维护者试用产品约 60%，面向普通用户的完整产品约 35%–40%。**

## 推荐优化顺序

### 第一优先：把入口变成一句话真的跑到底

目标：用户只说“开始这个 case，目标是……”，主 Agent自动进入正确能力、完成成员和复核，只有需要选择或纠偏时再问用户。

建议合并解决：

- 允许模型自动加载一个只负责路由、无副作用的轻入口；
- daily goal 返回明确的下一步，或在一次用户操作内继续到复核；
- `status` 只给一条普通话当前动作，不暴露内部 actor、hash 或占位命令；
- `continue` 默认选择唯一最合理的工作线，多选时用人话列出差异；
- 统一 `rekit` / `rekit-host` 的安装后命令和参数体验。

这是投入回报最高的一步，因为核心能力已经存在，主要差的是把内部两三段动作藏起来。

### 第二优先：打通“已有目录/已有样本”安全接入

目标：用户指向一个已经有资料的目录时，不报生硬错误，也不静默接管。

推荐：

- 自动识别“普通目录、已绑定 case、全新路径”；
- 对普通目录生成零写入接入预览；
- 用一句问题确认“在原目录建立 case，还是旁边新建 case”；
- 明确绑定 `targetArtifact` 和最初证据，而不是让成员猜目标文件。

### 第三优先：做一个真正有用的只读领域工具闭环

不要同时扩 8 个 pack。优先给 `vmp-re` 做一条真实、低风险、高频的只读链，例如：

- 读取用户已有 IDA 导出、函数索引或 trace 摘要；
- 由 runtime 发起受限查询；
- 工具结果自动登记为证据；
- 成员引用结果交稿；
- 独立复核检查引用是否真实。

这会把项目从“会组织读资料的 Agent”推进成“能借助领域工具真正推进任务的系统”。

### 第四优先：收紧稳定性绿灯并做可复核发布

- soak 只允许有明确结构化类型的复核语义/前后关系失败重试；普通错误文本不应触发。
- 让正式发布检查真正执行全部命令并产出绑定当前版本的单一结果，而不是只检查清单存在。
- 恢复当前 HEAD 的 Windows/Linux/macOS 远程检查；Windows 日常产品仍可先行，不必等待跨平台功能完全对等。
- 提供预编译 `rekit` / `rekit-host`，减少 Go 环境要求。

### 第五优先：再扩第二个深 pack

等入口和真实工具链跑顺后，从 `web-security` 或 `generic-binary-re` 选一个，把它从骨架做成第二条真正可日用路线。不要同时给 8 个 pack 添模板文字。

## 结论

- **现在能用吗？** 能，但适合维护者或愿意试用的高级用户，首选 Windows + `vmp-re`，由主 Agent代管内部步骤。
- **能拿来稳定做真实 case 吗？** 可以开始小范围试用，尤其适合已有文本证据、导出结果和明确目标的 case；不要把它当成自带完整逆向工具链的自动分析器。
- **能给普通用户直接安装使用吗？** 还不能。
- **最值得做什么？** 先把自然语言入口、第二段复核、已有目录接入和默认继续合成一个顺滑闭环；随后给 `vmp-re` 接一条真实只读领域工具链。
