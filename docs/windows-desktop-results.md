## 失败与修正

桌面验收前两次均在发送任何 MCP 键鼠前停止：先报前台不符，再报窗口被遮挡。定点诊断证明窗口实际可见、采样点均属于自建窗口，根因是 Python 虚拟环境启动器 PID 与实际窗口子进程 PID 不同，临时验收脚本比错了进程。

修正仅发生在临时验收脚本：以目标自行写出的 PID 与原生 HWND owner 交叉核对，再检查截图区域和输入点归属；点击后仍检查前台焦点。重新执行上述截图、点击、键入与清理全部通过。未关闭 MCP 接管保护，未自动点击权限确认，也未修改或操作其它软件来使验收通过。

提交前再次执行 Go contract 时发现：Python 单元测试导入 `dm_docs.py` 会在产品目录留下 `__pycache__`，触发构建残留检查。已在测试导入期间临时禁写字节码并清理该定点残留，不放宽产品检查；按“完整 Python 85 项 → Go contract”的原失败顺序复验通过。

## 未验边界

- 本轮未做 Windows 11 实机验收、无 WezTerm 标记时独立新窗口的前台验收、多屏/其它 DPI/缩放组合；对应机械测试不能代替这些实测。
- 自建窗口通过不等于所有软件或游戏可用；未操作真实游戏、提权窗口、UAC、安全桌面或独占全屏，也未验证长期无人值守。
- 本轮未测所有 MCP 工具的实际效果；`Snapshot`、滚动、快捷键等只核对协议暴露，不借截图/点击结果宣称其已实操。
- 关闭包遥测不是全部依赖运行期零出站证明。工具可能将截图/UI 树带入模型上下文，正常使用仍按获准窗口与配置域控制范围。
- 本轮结果不提升历史研究效果、Reviewer calibration、learning 或 Release 门槛。大漠/MFC 的独立验收范围见该工程 README，不能用桌面 MCP 结果替代。
