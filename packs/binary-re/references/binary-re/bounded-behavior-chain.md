# 有界行为链与预测验证

用于用户的问题跨越参数处理、字段转换、函数调用或后续消费者等实质性边界时。目标是说明一段行为为什么成立，而不是把几个函数的摘要串成故事。单函数局部效果仍使用原来的 function review；低样本 final effect 按需读取 [Singleton handler 复核流程](singleton-handler-review.md)。

## 先圈定一条短链

从任务指定的 case-local artifact/E 选择与问题直接相关的少量步骤，明确起点输入、终点行为及停止位置。不要求遍历整个程序、恢复所有函数或生成完整调用图。

- 对齐 binary/build、架构、地址基准、对象及观察范围。数据库状态、反汇编、摘要与实际运行可能来自不同版本，不能默认合并。
- 区分当前路径、静态可达路径和实际发生的调用。静态 call/xref 不能独自证明该次输入走过此路径；间接调用的目标未确定时留下断点。
- 若需新的指定函数/调用点材料，按 [IDA 定点函数取证](../../tooling/recipes/ida-function-evidence.md) 单独核对工具条件、读取范围、输出预算与具体动作许可。已有 export 的再次阅读不是新的独立观察。

## 每个关键连接都要有依据

把说明写进现有 F 正文，直接引用对应 E 的定位，不新增链数据库或任务字段。

| 连接问题 | 应核对的证据 | 不能据此推定 |
|---|---|---|
| producer 的输出是否进入 consumer | 同调用/对象范围的寄存器、参数、返回值、内存位置或明确转换关系 | 变量同名、两个摘要相似就代表值已传递。 |
| 中间有没有改变值 | wrapper、截断/扩展、符号性、编码、默认值、重叠写和 alias；读取时点须明确 | producer 出口值必然等于 consumer 读取值。 |
| 使用的是不是同一对象/状态 | 对象来源、生命周期、调用前态与可追溯读写位置 | 地址相同就代表对象或内容未变。 |
| 分支条件是否满足 | 实际比较、边界值、错误路径、调用约定及当前输入约束 | 静态可达就表示该次执行必然到达。 |
| 是否覆盖终点行为 | 下游消费、返回处理和已知副作用；标明未覆盖的外部调用 | 中间值正确就证明完整功能正确或无副作用。 |

每条关键连接都应能回答“哪条 E 支持、在什么条件下成立、哪里仍未知”。一处未证连接不能用两端各自正确来补齐；先交付可证局部，并说明它对整体判断的影响。同源反汇编、xref 与导出摘要只能互相核对表示，不因数量增加就变成独立证明。

## 用未查看的行为检验解释

1. 选择一个会区分当前解释与竞争解释的分支、调用点或输入条件；不要只选择两种解释都会给出同一结果的观察。
2. **查看该观察前**，在现有 F 或任务已有的 replay spec 中写下预测、所依赖的条件和反驳结果。保留原预测与输入条件，结果到来后追加实际判断，不倒改成“原本就预期如此”。原生 session 中的先后记录或已绑定的 spec 可支持时间顺序；事后填写不证明预测在先。
3. 优先读取尚未查看且来源可核对的有界材料。若需执行、调试或其它新动作，重新核对具体授权、工具权限和停止条件；静态读取许可不授予目标执行权。
4. 比较预测与观察：符合只支持实际覆盖的条件；不符先定位错误连接、前提或观察身份，不用更多同类支持材料掩盖反证。仍不可区分、缺材料或未获准执行时保留 unknown，而非“已证伪”。

不能将已经看过的结果换一种说法称为预测验证；一次分支符合不证明所有输入或整个程序行为。若需要 proof-carrying replay，复用现有 spec/result/E/R，不另建执行器。

## 综合交付与复核

- owner 单写一个回答当前问题的综合 F：短链、连接条件、预测与检查结果、反证影响和未覆盖范围。综合 F **直接引用全部支撑连接的 E**；局部 F 只能作为导航，不能替代 E。
- verifier 只复核最影响结论的一处连接或预测，不默认重跑全部研究；同源再次导出不自动授予 V2。
- Reviewer 同时审查连接与终点 claim，并在整体 review 中绑定综合 F 和全部相关 E 的 current SHA。两个局部 accepted 不等于整体 accepted；当前系统不递归验证 F→F 依赖。
- 输入或连接证据变化时，按现有 currentness 规则复审；无后台图或自动失效传播保证。正式改派、成员单写与用户纠偏优先级不变。

若问题进一步跨到 API，先提供当前客户端 build、对象/操作、字段来源和转换位置、请求构造与响应处理的 E。仅当 Web 方法确有必要且 `web-security` 已是固定主/辅助包时，由 Commander 把其 manifest/router 及 `../../pack-snapshot/packs/web-security/references/web-security/client-api-joint-review.md` 写入成员输入。该路径以成员目录为基准；不补装辅助包、不默认跨包读取，也不把联合方法全文复制到本包。

## 合成抽象案例

以下只解释方法，不是真实二进制、trace 或审查结果。

- **正向**：函数 A 产生一个已验证的计数，连接材料显示它以同一位宽传给 B；B 的零值分支会直接返回。查看另一调用点前预测“计数为零时不会进入消费者 C”，新的有界材料符合。支持该构建、输入和覆盖范围的解释，不外推所有调用者。
- **反例**：A 的输出与 C 的输入分别看似合理，但 wrapper B 在中间截断高位。新观察否定“原值无损进入 C”，应修正该连接与依赖它的终点结论，不能只给旧报告补一条例外备注。
- **unknown**：已知 A 写出字段、C 读取同名字段，但对象身份和中间间接调用未核对。两端可分别描述，不能建立 A→C 因果关系；下一步只核对该调用的对象/参数，缺材料就停止。
