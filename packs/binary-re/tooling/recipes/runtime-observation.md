# Runtime observation（Windows 定点运行时补证）

对静态结论做最小运行时对照：先预测、后运行、保留差异。这是 Windows 动态补证的最低成本官方入口；x64dbg MCP / bounded debugger action 可用时按 `ida-x64dbg-mcp.md` 升级。

## 前提

- 仅运行授权合成或明确获准的目标；记录目标 hash 与运行环境。
- 先写下静态预测（哪些输入会触发什么输出/行为），再运行；不事后编造预测。

## 步骤

1. 静态预测：从功能链推导至少一个可观察输出（stdout/exit code/文件副作用），写明支持与推翻条件。
2. 运行观察：以普通进程运行目标（合成目标或获准副本），捕获输出与退出码；记录命令与时长。
3. 对照：预测命中 → 静态链获得运行侧支持；不命中 → 收窄或修正静态结论，不丢弃反例。
4. 需要内部状态（寄存器/内存/断点）时才升级到调试器入口，并满足其 heavy action 边界。

## 边界

- 运行目标属于执行动作：合成 fixture 在 case 授权内可直接运行；其它目标须具体确认。
- 不自动附加调试器到任意进程；探针结果不跨版本/输入复用。
- 观察不到内部状态时，结论保持"输出级对照"，不声称内部路径已证。
