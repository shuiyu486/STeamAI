# Game Automation 工具路由

工具选择遵循"绑定明确批准的目标、可观测状态、有界恢复"。pack 只描述能力和边界，不执行工具、不代装依赖。

## 按任务路由

| 任务情况 | 首选 | 边界 |
|---|---|---|
| Windows 桌面游戏窗口自动化（图像识别、键鼠输入） | Airtest（`../../tooling/integrations/airtest.md`） | 固定版本；先环境预检再实操。 |
| 目标提供 SDK/控件树（Unity/UE/Cocos 等） | Airtest + Poco | 仅当目标确有控件支持时；无 SDK 不承诺控件树，图像识别兜底并声明不确定性。 |
| 浏览器内游戏 | Playwright（仅在 case 已冻结 web 主/辅包并按其 integration 使用） | 本 pack 不捆绑 web 依赖；无该包时不引用其 pinned 文件。 |
| 移动端（Android/iOS） | 不在本 pack 首版范围 | 需要时另立路线，不静默降级到桌面方案冒充。 |

## 状态含义

| 状态 | 含义 |
|---|---|
| `mainline-template` | 固定版本、可重复的官方入口。 |
| `auxiliary` | 特定前提（如 SDK）下使用。 |
| `candidate` | 版本或运行接口尚未现场验证，只记录预期。 |
| `cautious` | 有输入注入、非幂等动作风险，必须具体确认。 |

## Heavy action

向目标窗口注入输入、执行非幂等操作前，向用户展示 exact 目标绑定、动作、预算（次数/时长）、失败与停止处置、产物位置与回滚方式。确认只授权该具体动作；目标、范围或状态变化时停止并重新确认。

## 维护规则

- 新工具先写 integration/条目（固定版本、官方来源、运行时限制），再进入 catalog；catalog 永远不作为可解释执行命令。
- 环境预检失败、版本不符、目标绑定不明确时如实报告缺口，不以替代流程冒充同等交付。
- 真实游戏身份、凭据、未脱敏截图、绝对路径不进入 pack。
