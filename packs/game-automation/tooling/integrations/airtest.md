# Airtest 专业能力接入（game-automation）

## 目的

Windows 桌面游戏自动化脚本开发从任务开始使用固定版本的 Airtest；不先手搓坐标点击、不把全桌面截屏当状态源。

## 固定版本与来源

- Python 包：`airtest==1.4.3`（PyPI 官方发行，1.4 系列终版）；运行时要求 Python ≥3.8（本机维护基线 3.12，兼容性以环境预检实测为准）。
- 可选 `pocoui==1.0.94` 仅当目标确有 SDK/控件树支持；无 SDK 不安装、不承诺。
- 依赖只在获准环境安装（属新安装，需用户批准与恢复方式）；pack 不代装、不升级宿主、不维护工具配置管理器。固定的是方法材料与接入合同，不是运行环境。

## 运行接口（官方形态）

- 状态识别：`airtest` 的 `Template` 图像匹配（带 `threshold`、`rgb` 参数）或窗口 API 查询；坐标断言须处理阈值、缩放与遮挡的不确定性，不把绝对坐标常量当可靠通用能力。
- 动作执行：`touch`/`swipe`/`text`/`keyevent` 等官方 API，只作用于任务列出的 exact 目标窗口绑定。
- 脚本以普通 Python 进程运行（`python workflow.py` 或 Airtest IDE 导出脚本经检查后使用）；无守护进程、无后台服务。
- 每个等待用状态轮询（有上限、有间隔上限），不堆叠固定 sleep。

## 环境预检（DLV-02 冻结，实操前现场执行）

1. 获准安装后 `pip show airtest` 核对版本为 1.4.3；记录 Python/平台。
2. 用合成测试窗口（仓库外生成，非真实游戏）完成一次低影响真实操作：绑定窗口 → 识别一个状态 → 执行一个安全输入 → 观察结果 → 释放连接。`--version` 或 import 成功不等于可用。
3. 预检失败（版本不符、依赖冲突、窗口绑定失败）时报告具体缺口与影响，不启动后续实操。

## 目标定位方法分层（按稳健度优先，不默认模板匹配）

自绘游戏窗口没有 UIA 控件可枚举，定位只能走视觉；按以下顺序选择，不把标定敏感的模板匹配当默认：

1. **原生控件枚举**：目标是标准控件窗口（非自绘）时，`EnumChildWindows`/UI Automation 取控件 rect，通常比图像标定直接；仍须核对 DPI、坐标系与目标控件支持。
2. **LLM 视觉定位**（自绘窗口、慢速有界流程的默认候选）：截图（目标支持时可用 PrintWindow+PW_RENDERFULLCONTENT 穿遮挡，ndarray 注意 BGR→RGB 与 DPI 对齐）→ headless `claude -p` 读图返回 JSON bbox → 复核停止与状态后点击。旧评测历史报称合成窗口 green/orange 两状态误差 ≤1px、逐次 CLI 调用约 30–60s；本轮未重新核验这些数字，不代表当前模型或任意动态 UI、渲染后端可靠。逐次模型调用不宜用于实时循环；定位调用放在 adapter 的 `prepare` 阶段并接受 Runner 传入的 checkpoint（调用期间反复轮询控制文件，stop 立即放弃并丢弃过期坐标），返回后由 Runner 复核再发输入。放宽 join/等待超时只解决编排问题，不解决停止与状态过期。
   - **定位蒸馏**（重复动作的性能方法）：首次 llm 定位成功后把 bbox 区域裁剪为本次运行内的本地模板，后续同目标先本地模板匹配（毫秒级），命中直接用；失配（外观/尺寸变化、渲染竞态）自动回退 llm 重定位并更新模板，模板匹配是全图搜索所以窗口位移可被跟踪。旧评测环境历史报称：首次 28.2s、蒸馏命中 0.013s——仅为历史记录，不代表当前实测，也不外推为全任务加速；本仓库合成通路当前实测参考值见下。纪律：只存内存不落盘（进程重启即失效，符合重启不带状态的语义）；缓存 key 区分目标实例/动作/状态，帧尺寸变化即失效；失配回退、歧义/低纹理（逐通道空间 std，纯色不论颜色一律拒绝）/越界/坏 bbox 一律安全失败不猜坐标；定位期间目标变化由 adapter 凭冻结的 frame revision 在发输入前拒绝，不靠点击落点事后判定；本地匹配是单次同步 OpenCV 调用（本仓库 480x320 合成图实测约 8ms，时长受截图尺寸约束），停止只在调用前后 checkpoint 生效，不承诺调用期间可取消；蒸馏命中不豁免坐标校验与点击后状态复核——本地命中只是"目标看起来还在"，是否点对由目标端反馈判定。仓库内参考实现：`tooling/examples/windows-flow/localize.py` + `synth_device.py` + `synth_target.py`（策略单测零依赖，图像路径需 numpy/opencv，缺失 skip；`CvMatcher` 直接用 OpenCV `matchTemplate`，与 aircv/airtest `find_template` 同一原语）。
3. **模板匹配**（aircv）：仅极简单、静态、渲染可控的场景；对 DPI 缩放、坐标系表示（BGR/RGB、ndarray/PIL）、标定后渲染变化敏感——失败时先怀疑坐标系与截图管线，不要在阈值参数上打转；collect 等多色块场景颜色掩码要把按钮与背景装饰分成独立 band，不能整图 min/max 合并。

选择记录在脚本入口（如 `DLV05_LOCATE=llm|template`），验收报告注明所用定位方式。

## 失败/停止与恢复

- 窗口失焦、目标消失、意外弹窗、识别低置信度：暂停或安全停止，不盲点、不无限重试。
- 意外弹窗：遇 DIALOG 一律暂停。合成验收 fixture（`tooling/examples/windows-flow/synth_target.py`）的弹窗必须有关闭路径——`popup_close_after_ms` 可选正数到时自动关闭、默认永久持续，亦可显式关闭；弹窗关闭本身不触发恢复，恢复只来自显式 resume（修复历史 fixture"弹窗无关闭路径、任务不可达"的缺陷）。
- act 确认合同：adapter 返回 True 表示目标预期结果已确认（不只是输入已发出）；未确认（非 True/异常/目标拒绝）保留 pending、不 commit、不重试，暂停等待确认。
- 停止判据：收到停止到不再发新输入 ≤2 秒（无法满足时记录实测上界并修复，不把"按键已发送"当停止完成）；长阻塞库调用须可中断或用独立停止机制。
- 恢复前重新观察实际状态，不从旧计数器继续；只对安全、幂等或已确认未发生的动作恢复。
- 紧急停止入口独立于主循环；结束释放本次连接与自有资源，不关闭用户游戏、不清除用户存档。

## 产物与证据回交

- 运行日志说明步骤、观测、决定与失败原因；失败截图只裁目标区域、存 case 内，避免采集其他桌面敏感内容。
- 测试观察按 evidence 记录（命令、输入配置、观察结果、限制）；代码交付走 code review，绑定源码版本或 exact diff。
- 脚本、配置模板、依赖锁（`requirements.txt` 固定 pin）与使用说明交付在分配的项目路径；示例配置只用合成窗口与占位符。

## 不支持什么

- Android/iOS 设备自动化、多游戏引擎适配、反检测/反作弊规避不在本 pack 首版范围；浏览器内游戏走 Playwright（仅当 case 已冻结 web 包）。
- Airtest 不能替代不属于自动化脚本职责的动作（账号注册、支付凭据处理等），这些一律交用户。
