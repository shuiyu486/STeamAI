# 大漠专业能力接入（game-automation）

## 何时使用

用户明确选择大漠（dm / dmsoft），或已有大漠＋按键精灵的字库、识别参数和已跑通过的流程时，从本入口评估复用。大漠与 Airtest 并存：前者可延用既有字库与窗口操作经验，后者保留 Python 图像自动化和现有参考工程；按目标、已有资产及实测结果选择，不强迫换工具，也不默认同时运行两套输入通道。

本入口提供离线接口资料、版本更新工具与 C++/MFC 基础工程，不是自动执行入口。已有 7.2520 资产先读 [`../../upstream/dm-7.2520/README.md`](../../upstream/dm-7.2520/README.md)，再只打开当前接口页；不同版本先用 [`../dm-docs-update.md`](../dm-docs-update.md) 核对对应 CHM。C++/MFC 开发从 [`../examples/dm-cpp-mfc/README.md`](../examples/dm-cpp-mfc/README.md) 的实际源码开始，并读所用版本的线程/接口约束。资料与源码随 Fresh 固定到 case，成员无需额外插件或联网即可查用。大漠 DLL、完整 CHM、原脚本、字库、注册码和真实窗口参数仍由用户保留在授权位置，不进入 canonical pack；离线资料可用不等于已完成大漠调用或真实游戏验收。

- 读取顺序：本地离线目录 → 本次接口页；常用页不重复要求外部插件或重新拆 CHM。需要未收录内容或发生版本不一致时，才补对应 CHM，远程索引仅作辅助。只读取必要页面，不一次加载整个文档库；发现缺正文、参数或版本依据时记录缺项。远程资料按用户批准的读取范围取用，不把旧脚本、凭据或游戏截图发送到外部服务。

## 已有成果如何复用

只读盘点与当前需求有关的原脚本、字库、图片、清单格式和配置；记录编码、窗口尺寸/DPI、坐标系、识别阈值、成功检查与失败处理。旧脚本是需求和经验来源，不自动执行、不自动导入旧 STeamAI 状态，也不把历史“跑过”当成当前可用。

保留可验证的业务规则与资源；按键精灵专属的线程、热键、退出回调、文件读写和全局变量交接需在新项目内重新实现。注册凭据只经 private stdin 输入，不进命令行、日志或持久文件。具体迁移或新脚本只在用户分配的 case 源码范围内开发，支持接入不等于已获准迁移所有旧功能。

## C++/MFC 接入边界

基础工程不是只有指南：`tooling/examples/dm-cpp-mfc/` 包含 CMake、MFC 界面源码、C++ worker、自建目标 EXE（`dm_demo_target`）、COM 版本查询封装与合成测试。当前交付初始化/版本探针、开始/暂停/停止、日志、自建窗口测试与注册码密码框；MFC 按钮到 worker 的真实链路已实测通过：`Ver` → `Reg` → `BindWindow`(gdi/windows/windows/0) → `CmpColor` 正反 → click/`'A'` 各 exact 1 → `UnBindWindow` → 目标关闭（目标在 `CreateDesktop` 非活动桌面显示，不切换用户输入桌面）。不涉真实游戏、全局输入或游戏迁移，不包含识字、截图或具体游戏流程，落地与验证状态见工程 README。界面与 worker 都按 Win32（x86）＋VS2019 构建：与现有 x86 SDK 同位数，并静态链接 MFC/CRT，部署不依赖对应运行库 DLL。

1. **先核对位数**：加载 DLL 的进程必须与其位数一致。32 位 `dm.dll` 不能直接加载到 64 位 MFC 进程；64 位 Windows 不代表 SDK 是64位。可按已具备的工具链选择同位数应用，或界面＋同位数 C++ 执行子进程；不预先强制单进程或多进程结构，也不为接入升级 SDK。
2. **付费 `Reg` 的许可边界**：按文档 7.x 除 `Ver` 版本探针外的所有功能都需先完成 `Reg`。注册码是用户自己的，只在界面密码框输入、经父进程 private stdin 传给执行进程，不进命令行参数、日志或持久文件；每次确认都可能联网/计费；`ver_info` 是注册时传入的自定义版本信息，可空，不是 SDK 版本；版本核对仍用 `Ver`。缺少 `Reg` 批准、`Reg` 返回失败码或许可输入即停止，绝不调用 `BindWindow`。7.2520 实测：漏掉文档要求的 `Reg` 前置会在绑定阶段以访问异常退出，补 `Reg` 后同一 MTA、mode0 与直接 COM 工厂路径即可绑定。
3. **对象归属明确**：离线 `threading.md` 原文说明支持 STA/MTA，并建议高级语言使用 MTA；每个使用 COM 的工作线程负责初始化、创建对象、调用、解绑与释放，最后对称清理 COM。不要跨线程直接共享 COM 接口，也不能仅因 MFC/`CWinThread` 存在就声称线程安全；具体 C++/MFC 取舍见离线 `cpp-mfc.md`。需要 STA 时保持其消息处理能力，文档支持不等于并发实测通过。
4. **同一窗口串行输入**：同一目标只有一个动作拥有者；制作、切页等流程通过状态交接，不让多个线程同时点击同一窗口。确需多窗口才增加独立执行单元；字库切换、全局配置、许可和 SDK 全局限制分别核实，不能由“各有对象”推断完全隔离。
5. **界面不承担长循环**：MFC 界面线程只用于配置、状态和控制；执行层有界等待、检查停止请求。排队的窗口消息或界面处理程序可能被长任务阻塞，关闭窗口也不会中断正在阻塞的 DLL 调用；必须记录实际停止上界，不用强杀线程冒充安全释放。
6. **构建与交付**：在 case 内固定编译器、架构和 SDK 版本，保留可修改源码、构建方法、依赖清单及运行说明。EXE 不等于单文件；静态 MFC/CRT 免去对应运行库 DLL 部署，但大漠 DLL、字库等第三方依赖仍需单独核对，且 VC 运行库安全修复后需重新编译——静态链接是本基础工程在当前本机/内部交付的取舍，不宣称对所有对外分发通用推荐。不把 SDK 或注册码写进通用仓库。

参考：[Windows 跨位数限制](https://learn.microsoft.com/en-us/windows/win32/winprog64/process-interoperability)、[COM 单线程单元](https://learn.microsoft.com/en-us/windows/win32/com/single-threaded-apartments)、[MFC 多线程](https://learn.microsoft.com/en-us/cpp/parallel/multithreading-with-c-and-mfc)、[运行库链接选项](https://learn.microsoft.com/en-us/cpp/build/reference/md-mt-ld-use-run-time-library)。这些通用文档不能代替 exact 大漠版本说明。

## 分层验证与停止

- **只读准备**：确认用户选定版本、资料完整度、PE 位数和资源；SDK 文件存在不等于已经注册、许可可用或本任务实测可用。按 common 工具可用性四态报告，未知就保留未知，不自动扫描其它目录或启动目标。
- **SDK 最小调用**：仅在用户批准具体加载/许可动作后，创建对象 → 查询版本 → 释放，核对载入的 exact 文件。安装、系统 COM 注册、免注册加载、联网许可、绑定和输入都不是“读文档”的附带许可；注册、安装驱动（含大漠驱动级键鼠所需）、提权或修改全局配置按同一方式处理——未经本次明确批准不做，获准后按批准范围执行。
- **合成窗口验证**：另获具体批准后，在无真实游戏和凭据的目标上验证绑定 → 识别一个状态 → 一次安全输入 → 检查结果 → 解绑/释放。首选无窗口后台测试通道；实测从未显示的隐藏目标可绑定但取色失败（无画面），因此后台验收用 `CreateDesktop` 非活动桌面显示的自建目标——目标可绘制、用户屏幕无可见窗口、输入桌面不切换；只有被测行为必须用前台/真实鼠标时，才在用户同意的时间窗内执行并关闭自开窗口。不把原有 Airtest 验收当成大漠验收。
- **目标验证**：真实目标需另行确认 exact 窗口身份、绑定/输入模式、资源路径、次数/时长预算和停止办法。大漠可有后台绑定模式，但只有 exact 模式已获准并实测确认后台截图与输入都仍指向该目标时，非前台才不是异常；未验证后台能力或前台模式失焦时停止，不偷切前台输入。
- **持续检查**：目标消失、绑定失效、意外弹窗、低置信度、坐标系变化未重新校验、预算用完或用户停止时，不发新输入。恢复前重新观察，不使用过期坐标；不盲重试提交/购买/领取等非幂等动作。
- **停止与清理**：遵守 workflow 的收到停止到不再发新输入 ≤2 秒判据，覆盖等待和耗时 DLL 调用期间；未满足时记录缺口，不承诺实时或无人值守。结束释放本次对象/绑定与自有资源，不关闭用户游戏；独立子进程退出不等于按键状态或目标副作用必已恢复，清理结果要实际核对。

## 交付与未验边界

按任务交付源码/配置/构建说明、依赖版本、脱敏运行观察及 code review。单测或合成窗口只证明各自范围；DLL 可加载不证明目标可绑定，绑定成功不证明识别正确，输入返回成功不证明业务完成。

本入口不提供通用 DLL 调用器、adapter host、常驻服务、自动升级或自动安装。大漠的后台绑定、驱动级键鼠、DLL 保护等防护/驱动参数是插件自身的文档化能力，不构成单独红线：在已授权 case 内按任务需要正常选型与配置，与其它窗口/输入动作一样走逐项确认。归档未收录的接口按上文补读对应 CHM 后使用。大漠接入材料不进入 learningTargets，既有 case 的 snapshot 不自动补装或覆盖。
