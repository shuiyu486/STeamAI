# Automation regression（六场景验收与回归）

自动化脚本的验收与改动后回归用同一场景矩阵；跑不全矩阵不算通过，也不算回归完成。

## 场景矩阵

| # | 场景 | 注入 | 通过判据 |
|---|---|---|---|
| 1 | 正常完成 | 无 | 走完全部状态到结果，非幂等动作恰好一次 |
| 2 | 延迟等待 | 加载延迟超过单步常规时长 | 状态等待内完成，不误判失败、不提前重试 |
| 3 | 错误状态拒绝 | 意外弹窗 / 未知状态 | 暂停或安全停止，不盲点、不无限重试 |
| 4 | 暂停恢复 | 暂停后注入位移/状态变化 | 恢复从重新 observe 开始，正确接续，无多余输入 |
| 5 | 紧急停止 | 运行中触发停止 | 收到停止到不再发新输入 ≤2s（记录实测值）；目标未被脚本关闭 |
| 6 | 重复启动 | 中断后重新启动脚本 | observe + ledger 判定非幂等动作已执行，不再触发；窗口侧非法尝试计数不增长 |

## 步骤

1. 每场景独立目标副本/初始状态，互不污染；场景失败保留记录，修复后另开编号重跑。
2. 时间线与 ledger 落盘；停止时延用时间戳计算（停止信号时间 vs 最后一次输入时间 vs 退出时间）。
3. fake adapter 单测与真实窗口场景都在矩阵内：纯逻辑回归用 fake，端到端用真实（合成）窗口。
4. 改动脚本后：至少重跑受影响场景 + 场景 1/5/6（正常、停止、非幂等保护是底线）。

## 边界

- 无法满足 ≤2s 时记录实测上界与原因并修复，不得改判据。停止实测须注明触发阶段：等待/准备内检查点的上界是 poll 间隔；不合作同步调用的阻塞段上界为该调用实测耗时 + poll 间隔，须附本机实测采样。headless 通道必须校验点击坐标落在预期控件区域内，不校验坐标的通过不算识别与输入路径的验证。
- 观察与输入不是原子过程：对本轮观察已识别的弹窗/未知状态不发送流程动作；若状态变化发生在最后一次观察之后、输入执行之前或期间，在途输入可能已发出且无法撤回——动作若正常完成，下一轮观察到弹窗后暂停。"错误状态拒绝"场景只验证前者，不承诺后者零输入。
- 非幂等"恰好一次"依赖两阶段登记（输入前 pending 落盘、成功后 commit，原子替换写入）：中断后 pending 残留表示无法确认是否已执行，重启必须暂停等待确认，不得当作未执行重发；登记文件损坏时 fail-closed 报错，不当空。
- 场景通过不等于真实游戏环境验证；合成窗口结果如实标注适用范围。
