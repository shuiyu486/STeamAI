# 颜色格式与结果

这是维护者依据 `文字识别/Ocr.htm` 示例段和 `OcrEx.htm` 注意事项整理的阅读指南，不是原文逐字复制。源文件 SHA-256 见 SOURCE.md 对应行；实际参数以固定接口页和目标样本为准。

## Ocr 颜色参数

| 用途 | `color_format` 形态 | 原文依据 |
|---|---|---|
| RGB 单色 | `9f2e3f-000000` | `Ocr.htm` 17–19 行 |
| RGB 允许色差 | `9f2e3f-030303` | 20–22 行 |
| 多色 | `9f2e3f-030303\|2d3f2f-000000` | 23–25 行；最多 10 种，用 `\|` 分隔 |
| HSV | `20.30.40-0.0.0` | 26–28 行 |
| 灰度 | `#40-0` | 29–31 行 |
| 识别行间加分隔符 | `9f2e3f-000000,\|` | 32–35 行；逗号后是分隔字符串 |
| 按背景色识别 | `b@ffffff-000000` | 39–43 行；前缀 `b@` 表示颜色描述针对背景而非文字 |

表格中的 `\|` 是 Markdown 转义；传给 SDK 的字符是普通 `|`，不是反斜杠。这里没有指定目标窗口、真实截图或可直接执行的流程。每次识别只使用任务批准的区域；不能把旧示例的整屏坐标当默认范围。

`OcrEx` 返回 `字符0$x0$y0|…|字符n$xn$yn`，原文明确它**不支持 Ocr 的换行分隔方式**。`FindStr` / `FindStrFast` 的颜色说明引用 Ocr，但返回值是索引和输出坐标，不是 OCR 文本；具体见各自页。

## 不同接口的成功含义

- `SetDict` / `UseDict` / `BindWindow`：1 成功，0 失败。
- `FindStr` / `FindStrFast` / `FindPic`：0 可以是第一个匹配结果，-1 才是没找到。
- `FindColor`：1 找到，0 没找到。
- `CmpColor`：0 匹配，1 不匹配。
- `Ocr`：返回字符串；原文没有把空串区分为“画面无字”与“配置/截图失败”，调用方不能自行把空串解释为业务完成。
- `GetLastError`：原文要求紧跟被检查调用；中间其它 SDK 调用可能改变错误值。

输入 API 返回成功只表明调用层结果，不证明界面状态或业务目标完成；必须重新观察目标。
