# C++/MFC 接入指南

这是维护者依据本地 CHM 约束节选整理的开发指南，不是大漠官方 C++ 模板。可修改的基础工程位于 `tooling/examples/dm-cpp-mfc/`（相对 pack 根），包括 MFC 界面源码、同位数 C++ worker、自建目标 EXE（`dm_demo_target`）、CMake 与合成测试。MFC 按钮到 worker 已实测完整真实链路：`Ver` → `Reg`（许可经 private stdin）→ `BindWindow`(gdi/windows/windows/0) → `CmpColor` 正反 → click/`'A'` 各 exact 1 → `UnBindWindow` → 目标关闭（目标在 `CreateDesktop` 非活动桌面显示，不切换用户输入桌面）。不涉真实游戏、全局输入或游戏迁移，具体游戏流程后续在独立项目开发。该目录 README 分别记录 C++ 构建、MFC 与真实 SDK 的验证状态。

## 先保留能用的成果

原有字库、识别区域、业务顺序和结果检查可以继续用；按键精灵的 `BeginThread`、全局变量轮询、退出回调、文件 API 和窗口界面不能逐句当成 C++。源码/字库/账号配置留在独立项目；不上传原脚本，也不抄出注册码。

对象初始化的逻辑顺序是：确认 SDK 身份与进程位数 → 初始化工作线程 COM → 创建对象 → `Ver` 核对版本 → 按文档完成 `Reg` 再使用其余功能（7.x 除 `Ver` 版本探针外所有功能都需先 `Reg`；7.2520 实测漏掉 `Reg` 前置会在绑定阶段以访问异常退出）→ `SetPath` / `SetDict` / `UseDict` → 获准后绑定 exact 目标。`Reg` 只用用户自己的注册码：在界面密码框输入、经父进程 private stdin 传给执行进程，不进命令行参数、日志或持久文件；每次确认都可能联网/计费；`ver_info` 是注册时传入的自定义版本信息，可空，不是 SDK 版本；版本核对仍用 `Ver`；缺少 `Reg` 批准、返回失败码或许可输入即停止，绝不调用 `BindWindow`。仅查版本的探针不调用 `Reg`，但加载第三方 DLL 不保证其内部绝不联网。这个顺序是开发参考，不是允许自动执行全部步骤。

## 位数与界面

加载 SDK 的进程必须和 DLL 位数一致。32 位 SDK 无法直接加载到 64 位 MFC 进程；64 位 Windows 可以运行 32 位程序，这与目标窗口属于 32/64 位是两个问题，不能由宿主位数推断目标绑定能力。

按现有工具链选同位数程序；界面和任务可以用独立线程，也可以用窄职责执行子进程。当前基础工程复用已有 C++ worker，MFC 界面不承担 SDK 同步阻塞，保留界面/执行/自建目标三个 EXE，不代表所有项目都必须多进程。不要为了“支持大漠”增加 STeamAI 通用运行器、服务或远程控制层。编译器与 MFC 版本由具体项目确定（基础工程按 VS2019、Win32、静态 MFC/CRT 构建），文档接入不安装这些工具。

## 线程和对象：本地文档已给出的约束

- `threading.md` 的“其他高级语言”原文明确支持 STA/MTA，建议高级语言使用 MTA，并要求每个工作线程初始化 COM。这比外部插件的空 FAQ 有实质依据，但**文档声明仍不等于目标实测**。
- C++ 可按 SDK 模型在工作线程使用 `CoInitializeEx(nullptr, COINIT_MULTITHREADED)`；检查 HRESULT，成功的初始化与 `CoUninitialize` 配对。不把已经初始化为另一模型的线程强行改成 MTA，不在 MFC 界面线程跑长循环。
- 每个执行单元拥有自己的对象；对象创建、调用、解绑和释放保持清晰归属，不跨线程裸传接口指针。MTA 支持不等于同一个对象可以随意并发重入。
- 多窗口可各用一个对象。确需同窗口多对象时，原文要求绑定模式一致、主绑定先完成、主绑定线程保持存活；主绑定失效会影响副绑定。同窗口输入仍应串行，不能让识别线程和动作线程同时抢键鼠。
- `EnableShareDict.md` 明确全局字库的主对象不能提前释放；先设置好字库，其它对象再开启共享；使用期间不能任意修改字库。不能用 `object-scope.md` 的默认规则否定这个例外。
- `input-channel.md` 明确 DX 键鼠绑定时必须使用大漠自己的键鼠命令。保留 Airtest 是保留另一工具选择，不是对同一个绑定窗口交错发两套输入。

## 返回值、状态与退出

COM 调用 HRESULT 与大漠业务返回值分别检查，尤其 `FindStr` / `FindPic` 的 0 是有效索引，`CmpColor` 的 0 是匹配。`intX` / `intY` 等“变参指针”是输出参数；C++ 封装需依据实际类型库/官方声明处理 VARIANT/BSTR 生命周期，不从 VBS 原型臆造 DLL 导出函数或参数类型。

MFC 界面只负责配置、状态和控制。后台执行定期检查停止，停止后不发送新输入；同步 SDK 阻塞不能靠窗口消息、界面处理程序或关闭窗口自动打断。正常退出停止接收动作、等待工作单元收尾、解绑、释放对象、清理 COM；不要把按键精灵 `OnScriptExit` 当成 C++ 中自然存在的保障，也不把强杀线程当正常清理。

通过普通单测验证状态与结果处理，再在获准的合成窗口验证版本/字库/绑定/输入/停止/释放。真实游戏和并发可靠性另验；本指南不预填通过。
