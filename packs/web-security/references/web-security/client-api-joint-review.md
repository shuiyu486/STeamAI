# 客户端/API 联合复核

用于同一明确授权 case 内，用户的问题必须结合客户端/本地模块与 API 两侧材料才能回答的情形。目标是一份有连接依据的联合结论，不是两份局部报告并排，也不是创建第二个 case、额外 pack 依赖系统或新的联合研究角色。

本文件是联合方法的唯一完整入口。Web 主包已有充分客户端 E 时可以使用；需要 Binary 专业方法时，只读取已冻结辅助包的任务指定入口。Binary 主包需要本方法时，必须已在 Fresh 固定 Web 辅助，且 Commander 已把对应 manifest/router 和本文件的 member-relative snapshot 路径列入任务；不自动补装或回读 canonical source。方法来源的 pack revision/snapshot digest **不能替代目标两端的 build、部署或协议身份**。

## 先圈定同一次业务问题

选择一个对象、操作和少量关键字段，明确客户端起点与用户关心的终点。首批操作范围是客户端字段编码/GET 构造 → 同对象 API 读取 → 客户端解析/错误分支，配合有来源的预置状态和版本；不为了“联合”增加 POST、请求 body、批量扫描或后台重试。

优先用现有 E 说明两侧已知事实与缺口。已有代码路径不证明客户端实际执行，已构造请求不证明请求实际发出，服务端返回也不证明客户端采用了该返回。将静态关系、实际发生的观察和推断分开。

## 逐段核对关键连接

在现有综合 F 中用短表或短链描述，只记录影响当前结论的映射；每一段直接引用相应 E 定位。

| 连接 | 应证明的内容 | 常见的错误拼接 |
|---|---|---|
| 客户端 build ↔ API 环境/版本 | 构建、配置/feature flag、协议或部署版本与观察范围如何对应 | 两端使用同名接口就默认版本一致；用 pack tree 代替目标版本。 |
| 本地对象 ↔ 服务端资源 | 本地操作怎样确定资源标识、请求关联、身份/角色/租户及归属 | 字段同名、时间接近或展示名相同就当成同一对象。 |
| 本地字段 ↔ wire 表示 | 字段来源、相关编码/规范化、宽度/符号、枚举、精度、默认值及缺省/null/省略差异 | 看到本地值就假定原样上网；忽略序列化或 wrapper 转换。 |
| 请求构造 ↔ 实际发送/响应 | 该次操作对应的真实 method、origin、path、身份与响应来源/完整性 | 静态构造调用等于成功发送；curl exit code 等于服务端拒绝。 |
| 服务响应 ↔ 业务结果 | 受限字段或可观察业务状态与权限规则的对应 | 状态码、body hash、UI 成功提示等于最终业务效果。 |
| 响应字段 ↔ 客户端处理 | 解析、错误分支、缓存/乐观更新与本地结果的联系，哪些实际发生、哪些仅静态可达 | 服务端拒绝就必然正确显示失败；旧缓存值当成本次响应。 |

无法获取服务端内部实现时，只说明该输入下可观察的服务行为，不将外部响应推断为已证明的内部实现。两侧材料来自同一导出或转述时，不能因为分属两个 pack 就变成独立证据。

## 把约束放回真正执行的位置

每项与结论有关的限制都说明执行位置、证据和未知部分：

- **客户端约束**只证明客户端在覆盖条件下如何构造或拦截输入；不能推出服务端同样拒绝。客户端不能产生某输入，不等于服务端对此有约束。
- **服务端约束**需要该目标环境下对应请求及业务观察；不能由客户端检查、API 文档或 schema 字段代替。
- **客户端结果处理**需要响应到本地分支/结果的联系；服务端行为正确，不代表客户端没有误报、沿用缓存或错误处理缺陷。

不因静态客户端限制较弱就自动发起绕过请求；任何新的输入或执行仍须满足具体动作授权。只证明一侧时，交付那一侧的局部结论，不通过提高 confidence 填补另一侧。

## 用一次区分性预测检验联合解释

1. owner 明确最关键的两种解释，以及差异落在哪条连接。例如是字段编码改变了对象，还是服务端对相同对象有不同权限行为。
2. 在查看新的分支/请求观察前，将最小条件变化、预测业务结果与反证写进现有 F 或已有 replay spec，保留原预测和条件。不能在看到答案后重新声明预期。
3. 补证只针对该连接。客户端新材料可按已分配的 Binary 方法取得；已有 [单请求方法](../../tooling/recipes/request-replay.md) 和 [curl 单次读取取证](../../tooling/recipes/curl-read-evidence.md) 负责请求动作边界；多次观察的可比性按需参考 [请求序列复核](request-sequence-review.md)。不默认串读所有方法。
4. 将新观察与预测比较，明确支持、反驳、仍不可区分或未执行。反证成立就撤回/收窄依赖该连接的联合解释；无法比较则保持 unknown，不把两个真实局部事实强拼为因果关系。

**停止条件：**build/环境无法对应、对象或请求关联不成立、字段转换不可追溯、发送不确定、输出不完整、预算/授权漂移时停止相应动作。保留已证明局部及一个最小补证，不自动 retry、改变目标或重新初始化状态来追求预期结果。

## 执行与团队边界

- 静态读取、IDA 定点导出、运行客户端、访问本地 API 是不同动作。客户端执行必须另行明确授权 exact 程序、输入、origin、允许输出、预算和停止条件，不能由 IDA 只读许可推导；预置/复位服务也是单独动作。
- 单次 GET 仍禁止 ambient config/proxy、redirect、retry 和 body；多个已批准动作不能被合并成无界循环。只读 evaluator 不执行本流程中的客户端或 HTTP。
- 一个 owner 对联合问题及综合 F 负责；最多一个 verifier 复核最薄弱连接，不因跨域自动扩编。持续改派由 Commander 决定，用户直接纠偏与成员任务单写规则不变。
- Reviewer 只审查整体 claim、连接、反证和 exact bindings，不接管取证或执行请求。`needs-evidence` 返回原 owner。

## 联合交付门槛

综合 F 必须直接回答用户问题，并包含：

1. 实际覆盖的客户端/API 版本、对象、身份及状态条件。
2. 一条有界连接链，每段**直接引用全部支撑连接的 E**；局部 F 仅作导航。
3. 约束在哪侧执行、预测与检验结果、反证和未连接部分。
4. 问题路径及合法路径的可证范围；没有合法对照不宣称修复无回归。
5. 绑定综合 F 与全部相关 E/artifact 的 current 整体 review。

两个局部 accepted 不等于联合 accepted。当前 E/F/R 合同不递归验证 F→F 图，不增加图数据库或自动失效传播；输入/证据变化按现有 stale/复审处理。原始运行材料留 case artifact，恢复沿用 native session，不建联合状态文件或 handoff。

学习仍只回主 pack，辅助方法和联合结果不扩大 destination 资格；主包经验必须自包含，不能隐藏依赖未来单主包 case 不具备的辅助路径、工具或执行许可。

## 合成抽象案例

以下是方法说明，不是真实程序、请求日志或审查记录。

- **正向**：客户端把对象 Q 的标识按已核对规则编码，关联材料证明本次 GET 确实指向 Q；服务端在指定身份下返回受限字段，客户端解析与最终显示也有对应观察。可以形成该条件下的联合解释；单次成功不证明其他版本或所有对象。
- **反例**：客户端界面阻止旁观者读取，原解释据此认为服务端也有同样限制。获准且对象/身份/版本匹配的 API 对照却返回了受限字段。该观察否定服务端限制的推断；保留客户端局部事实，不能以界面仍隐藏字段掩盖反证。
- **unknown**：客户端材料来自构建 A，API 观察来自无法映射的部署 B；两端对象名相同，但编码和请求关联缺失。两侧事实分别保留，联合结果 unknown；只提出核对实际字段/对象关联的最小补证，不拼出端到端结论。
