# 有界请求序列与预测验证

用于用户问题依赖前态、身份、对象以及后续读取之间关系的 Web/API 研究。多次请求不自动构成一条行为链；只做单请求归因时继续使用 [单一请求假设与有界复核](../../tooling/recipes/request-replay.md)，不强制增加序列表或成员。

首批实际操作路径是 [curl 单次读取取证](../../tooling/recipes/curl-read-evidence.md)：固定少量、分别获准的 loopback GET，结合明确来源的预置状态/版本。多步解释不要求 POST，不改变现有 request/result v1 的单次、无 body、无 redirect/retry/ambient proxy 边界，也不提供多步 runner。

## 先明确序列要证明什么

在现有 F 中圈定用户关心的起点条件与终点业务结果，只纳入会影响解释的步骤：

- 绑定实际环境/版本、身份/角色/租户、资源及归属、相关前态和观察时点。故意改变的身份是对照变量；会话意外失效不是同一种条件。
- 说明哪些材料是前态事实，哪些是一次请求观察，哪些能说明后续状态或合法行为。fixture 预置状态须有明确来源，不编成前一次 GET 导致的状态变更。
- 指明不同步骤之间的关联依据。时间接近、相同资源名、相同状态码或相似 body 不足以证明同一次操作、同一对象或因果关系。
- 无服务端内部材料时，只描述外部可观察行为，不臆造具体中间实现。

## 按连接而不是按请求数量补证

| 连接 | 最小核查 | 缺证时的结论 |
|---|---|---|
| 前态 → 本次请求 | 同一环境、身份、对象、状态来源与可比条件 | 前态未知，不能把结果归因于该前态。 |
| 请求构造 → 实际发送/到达 | 该次请求的来源和关联；区分本地构造、发出及服务端可观察接收 | 构造存在不等于已发送；缺记录不等于未送达。 |
| 响应 → 业务结果 | 与规则相关的受限字段、业务状态及观察完整性 | 状态码、body hash 或成功提示不证明动作完成。 |
| 一次观察 → 后续观察 | 对象/身份连续性、缓存/异步/并发因素、期间版本与状态变化 | 后续不同不能自动归因于前一步；先保留局部事实。 |
| 修复前 → 修复后 | 问题路径与合法路径分别在可比条件下验证 | 仅拒绝问题路径不足以声明修复无回归。 |

发送状态未知时先停止新请求，按单请求方法保留 `delivery-uncertain`；只有另行获准的状态核查才能继续，不自动重发以“补齐序列”。已到达但响应中止同样不能假定无副作用。GET 名称也不保证没有副作用。

## 预测一个尚未检查的条件

1. 从关键连接中选一个能区分解释的身份、对象状态或版本条件；不同时改变多个未控制因素。
2. 在查看对应观察前，于现有 F 或已有 replay spec 记录预期业务结果、反证及必要前提，保留原文和输入条件。事后重述结果不算预测。
3. 优先读取未查看的已有材料；新增请求仅使用已确认的具体动作和范围。预置/复位服务状态属于另一项动作，不能藏在 GET 配方中。
4. 新观察相符时只支持覆盖范围；不符时核对输入可比性，然后明确撤回或收窄哪条连接。若比较本身无效或材料仍不足，报告 inconclusive，不把受阻当成已推翻。

实际执行前展示具体目标、身份引用、请求数、时间/输出预算、可能副作用和停止条件；工具能强制的限额与操作约定分别说明。readonly evaluator 不因本方法获得网络或状态修改权限。

## 交付与协作

一个 owner 对用户问题负责，最多一名 verifier 复核最薄弱连接。综合 F 写清序列、各连接的条件、预测与实际结果、问题/合法路径和剩余未知；**直接引用全部支撑连接的 E**。局部 F 可导航但不构成递归证据闭合，两个局部 accepted 不能推出整体 accepted。

Reviewer 只读综合 F、相关 E 和已绑定 artifact，审查连接是否成立并记录整体 review；补证回原 owner，不执行请求。F/E/artifact 变化按现有 stale/review 规则处理。原始响应和较长日志留 case-local artifact，凭据不进入 E/F 或 pack；恢复仍用原生 session，不新增序列状态文件或 handoff。

当解释还依赖客户端构造、序列化或解析时，按需进入 [客户端/API 联合复核](client-api-joint-review.md)，不另起第二个 case。

## 合成抽象案例

以下只解释方法，不是真实请求、服务日志或审查结果。

- **正向**：抽象资源 Q 的归属与前态明确，已有合法读取可见字段 X；预测指定旁观者在相同对象/版本下不可见 X。随后获准的一次读取符合预期，仅支持这些条件下的权限行为，不证明所有接口安全。
- **反例**：解释声称修复只限制旁观者。预先预测合法所有者读取仍成功，但可比的新观察显示所有者也被拒绝。必须撤回“修复无合法回归”的部分，不能用旁观者被拒绝掩盖反证。
- **unknown**：两次读取显示不同对象状态，但期间异步处理、缓存和版本无法对应。保留两次局部观察，不宣称前一次请求改变了状态；先补其中一个能区分解释的关联事实，不自动重发或复位。
