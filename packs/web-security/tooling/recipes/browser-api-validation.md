# Browser + API dual validation

浏览器表现与服务端事实分开取证、再连接：同一假设在两侧都有观察才立得住。

## 输入

- 明确授权的本地/受控应用（origin/端口由任务列出），账号角色与对象已知。
- 待验证假设（权限边界、状态流转、响应一致性）。

## 步骤

1. API 侧：用独立 APIRequestContext（或既有 request recipe）按假设发受控请求，记录完整请求/响应/状态码与业务状态（如余额、归属）。
2. 浏览器侧：Playwright 独立 browser context 打开对应页面，真实交互后断言渲染结果；认证状态只在授权 case 私有区域使用。
3. 连接：说明同一输入在 API 响应与浏览器渲染上的一致/不一致；HTTP 200/403 或页面一行文本都不是完整证据，要核对实际业务对象状态。
4. 阴性对照：无效凭据、越权身份、非法状态各至少一条，证明拒绝路径存在且正确。
5. 只向批准 origin 发请求；第三方跳转不跟随。

## 输出与边界

- E：两侧观察 + 连接说明 + 阴性对照。
- 截图/trace 按敏感度留 case；token 不进 prompt 或通用报告。
- 需要写请求（提交/修改状态）时先取得该动作的具体确认；数据恢复用 fixture 显式 reset。
