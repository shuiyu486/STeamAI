# Fix regression（修复阻断 + 合法业务保留）

修复的验收是双面证据：问题被阻断**且**合法业务不受损。只证明其一不算修复完成。

## 输入

- 已实证的缺陷（finding + evidence：触发路径、前后业务状态）。
- 明确分配的项目源码路径（开发任务写入范围）。

## 步骤

1. 修复前基线：记录缺陷触发路径的当前行为与合法对照路径的行为（来自既有 E，不重跑无关项）。
2. owner 在分配路径内写最小修复（diff 绑定源码版本）；不为通过测试扩大改动面。
3. 回归双验（verifier 在获准环境复测）：
   - 缺陷路径：原触发输入被阻断（新状态码/新行为记录），且阻断方式符合业务语义（如 403/409，不是把所有请求都拒了）。
   - 合法路径：修复前通过的每个合法对照仍通过。
4. 状态残留检查：修复后应用状态与预期一致（无脏数据、无半支付订单）。
5. 交付：修复 diff、复测回执（双面）、限制说明；代码交付走 code review，不伪造安全 finding，accepted 不升级 learning 资格。

## 边界

- 不把"服务拒绝一切"当修好；不动授权范围外代码。
- 复测失败保留失败记录，修复后另开编号重测，不覆盖。
