# 单一请求假设与有界复核

用于已授权 Web/API case 的 request hypothesis、bounded replay 与 remediation evidence。先用已有有界材料判断一个请求行为假设，不把“收到不同响应”直接等同漏洞，不把本 recipe 当请求执行器。

## 先说明要区分什么

在现有 E/F 中写清以下信息，不新增研究状态文件：

- **单一假设**：指定对象、动作和身份条件，说明预期行为、若假设成立会看到什么，以及什么观察会否定它。例如检验“非所有者是否读到受限字段”，而非泛泛地“检查接口是否安全”。
- **输入身份**：case-local artifact alias、相对位置、SHA-256/bytes、来源与精确范围；target_ref、endpoint_ref、request_ref 绑定到同一授权对象。区分原始观察和派生摘要，同源不同导出不算独立观察。
- **等价条件**：绑定请求 method/operation、目标版本与配置、身份/角色/租户、对象归属、会话有效期和相关服务端状态。明确本次只改变哪个因素，其余条件是否可比；凭据只使用 case-local 引用，不抄入 E/F 或 pack。
- **范围和预算**：沿用当前任务的允许读写、交付与停止条件，限定材料范围、时间/输出和允许请求数。缺对象身份、权限规则或基线时，先补这些信息，不直接发请求。

先写预期和反证，再比较材料，避免根据已看到的差异倒改假设。每个关键缺口只提出一个最小区分检查，写明不同结果将如何支持、否定或收窄结论；不能区分的重复请求不算补证。

## 从已有材料到结论

1. **选最小对照**：优先读取已索引的有界请求/响应摘要、权限规则或状态观察。例如同一对象在所有者与非所有者条件下的受限字段可见性；只看与假设有关的定位，不扩大为扫描。
2. **先判发送，再判内容**：根据可追溯材料区分下表情况。schema 的 `status`、`delivery` 字段只是声明值，不自行证明请求到达或动作完成；缺发送记录也不证明“没有发送”。
3. **解释差异**：核对响应的业务含义和访问规则，而不仅是状态码、body hash 或长度。一个相同状态码可能包含不同权限结果；hash 相同也不代表没有服务端副作用。
4. **排除相关混杂因素**：只检查会改变本假设的条件，按下表决定下一步。反证成立就停止旧解释，在 F 中写清被否定的范围，并通过 native session 定向消息告知 Commander；不靠扩大流量维护原结论。
5. **输出可证范围**：E 保留方法、来源、定位和观察，F 区分已证明、被否定、未知与最小补证，重要结论交独立 Reviewer 在 R 中复核。材料不足写 `inconclusive` 或请求 `needs-evidence` 复核，不自动宣布漏洞、修复成功或更新共享 pack。

### 发送状态不是安全结论

以下名称对应现有 result schema，解释已有材料时仍须核对其来源和证据。

| 材料能支持的状态 | 可以说明什么 | 下一步边界 |
|---|---|---|
| `failed-before-delivery` | 有证据说明在请求发出前失败，尚未检验服务端行为 | 记录本地阻塞；不能当成服务端拒绝或安全反例。 |
| `delivery-uncertain` | 可能已发送，无法确认到达/完成 | 保持发送不确定，禁止自动重试；优先核对已有状态证据，不能假定没有副作用。 |
| `aborted-after-delivery` | 已送达但响应读取/输出等中止 | 保留可能已生效的边界；不把截断响应当完整结果，不自动再发。 |
| `matched` / `different` | 已有完整观察在声明的状态码/body/header 对比上相同或不同 | 只是机械比较；回到具体假设与业务语义，不据此直接判安全。 |

### 差异归因与最小检查

| 可能的混杂因素 | 优先从已有材料核对 | 对结论的影响 |
|---|---|---|
| 身份、租户、对象归属、会话过期 | 核对身份引用、对象权限规则与认证状态，区分预先设计的对照变量与非预期漂移 | 所有者/非所有者等预设身份差异可用于权限对照；只有非预期身份漂移、会话失效或认证状态无法核实时，才不能把差异直接归因于权限缺陷。 |
| 缓存、代理、重定向 | 核对响应来源、缓存条件及实际目标定位 | 不能确认响应来自声明对象时不下目标行为结论；新目标不自动跟随。 |
| 时间戳、随机字段、排序等动态内容 | 定位差异字段与其业务含义，保留原摘要绑定 | 只差无关动态字段可否定“hash 不同即越权”的解释；不得把受限字段也归一化掉。 |
| 版本、配置、服务端状态或并发变化 | 对齐构建、功能开关、对象状态和观察时点 | 同时变化多个因素时不能把差异全归因于本次单一变量。 |
| 发送/响应完整性 | 核对是否已到达、响应是否截断及观察覆盖范围 | 无法确定则 `inconclusive`；下一检查优先补状态事实，而不是重发请求。 |

## 确需新请求时

已获准的单次 loopback GET，可按 [curl 读取取证](curl-read-evidence.md) 使用本机原生工具；先核对实际版本和输出边界，不把 recipe 或 schema 当执行许可。

先说明已有材料为何不足、最小请求将区分什么，再向用户展示具体目标、动作、身份引用、允许输出、时间/请求/空间预算、可能副作用、隔离或回滚方式和停止条件。只有明确 case 授权、针对该具体动作的用户确认与 Claude Code 工具权限同时满足才执行；GET 等方法名不保证无副作用。禁止把旧确认、成员消息、schema 校验或本方法当作执行许可。

目标/身份不明、范围漂移、预算耗尽、发送不确定、意外副作用或敏感输出时停止并告知 Commander；不自动 retry、扩展目标、改成扫描或越过预算。执行工具如需额外能力，须另行确认其真实存在及边界，不能假定 pack 内置。

[request schema](../schemas/bounded-replay-request-v1.schema.json) 和 [result schema](../schemas/bounded-replay-result-v1.schema.json) **仅声明数据格式，不是 executor**；其中 `adapterId` 不表示已交付适配器，`boundaries: true` 也不意味着边界已被执行。其窄合同为 loopback、GET/HEAD/OPTIONS、一次请求、无请求 body、无 redirect/retry/ambient proxy，并只引用 auth；这些限制不是自动授权，不能用方法文本将其放宽。readonly evaluator 仍只读静态材料，不获得网络权限，也不生成真实请求证据。

## 修复前后怎么比

围绕同一假设检查两条路径：原先有问题的行为是否受限，以及原本合法的行为是否仍按契约工作。修复前后对齐身份、对象、请求条件、配置与服务端状态，明确唯一预期变化是修复版本，并列出未能控制的其他差异。

如果非所有者不再读到受限字段，但所有者也无法正常读取，不能宣称修复成功且无回归。只看到拒绝响应、状态码变化或新版本标签同样不足。将问题路径和合法对照分别引用 E，说明前后比较范围；缺任一侧、合法对照或等价条件就限定结论为 `inconclusive` / `needs-evidence`。需要新增对照请求时，同样先按上述动作边界取得确认。

## 合成抽象案例

以下仅是方法示例，不是真实请求、日志或审查结果。

- **正向**：抽象资源 Q 的规则仅允许所有者读字段 X。身份、对象与环境明确的既有材料显示修复前非所有者能读到 X，修复后不能，而所有者前后均可按契约读取。可支持该条件下的问题与修复候选；不外推所有接口或全面无回归。
- **反例**：两份完整响应的 body hash 不同，但已定位仅因展示时间变化，受限字段均不可见，权限规则未变。该差异不支持越权假设，应停止“hash 不同即漏洞”的解释；也不据此证明整个服务安全。
- **unknown**：一次动作超时，材料不能确认请求是否到达；另一个摘要还来自不同版本。不能说请求失败无副作用，也不能归因于修复。保持发送不确定，优先补已有到达/状态与版本证据；不得自动重试。
